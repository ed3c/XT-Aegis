# Architecture Decision Records

ADRs capture durable decisions, alternatives, consequences, and status. They explain why an architecture
boundary exists; code, tests, schemas, and evidence determine whether it is implemented.

## Numbering and lifecycle

- Use the next four-digit number.
- Status: Proposed, Accepted, Superseded, or Rejected.
- Link source intent IDs, issues, and follow-up evals.
- A superseding ADR links both directions.
- Do not rewrite accepted history; add a new ADR.

Current records cover deterministic control-plane authority, external policy integrity, read-only MCP,
and owned snapshot rollback. Issue #35 proposes the Harness orchestration ADR.
